# PhishGuard

Системы обнаружения фишинга в браузере на основе МЛ и репутации доменов. Это будет расширение для браузера (скорее всего хром) отправляет URL и флаги страницы на бэкенд, бэкенд считает риск и расширение показывает ответ (добавим еще причину позже).

### ML-модель по URL
- датасет PhiUSIIL (235 795 URL), метки приведены к виду 1 = фишинг, 0 = легитимный.
- утечка есть: все легитимные URL имеют вид `https://www.<домен>` без пути. перекос есть
- URL нормализуется до хоста, модель обучается на 17 фичах хоста (`ml/features.py`).
- LogisticRegression, RandomForest и XGBoost (`ml/train.py`). Итоговая модель — XGBoost: F1 0.78, ROC-AUC 0.86, FPR 3%.
- Сохранены `ml/model.json`, `ml/feature_names.json` и `ml/metrics.md`.

### Бэкенд (FastAPI)
- `POST /check` и `GET /health`.
- ML-модуль: вероятность фишинга и до 3 причин.
- Модуль репутации:
  - возраст домена по WHOIS, включая разбор ответов KazNIC для `.kz`;
  - Google Safe Browsing: ошибка с ключом-нужно будет задать новый;
  - сходство с брендами и тайпосквоттинг.
- Модуль контента: поле пароля без HTTPS, форма на чужой домен, бренд в заголовке.
- Агрегатор с весами 0.5 / 0.3 / 0.2, белым списком и порогом Safe Browsing.
- Кэш с TTL 1 час. URL в логах и кэше хранятся без query-параметров.
- Время ответа без WHOIS 10–30 мс, с WHOIS до 2.5 с.

## Запуск

```
python -m venv venv
venv\Scripts\activate
pip install -r backend/requirements.txt
python ml/train.py
uvicorn backend.main:app --reload
python -m pytest
```
